IMPORTANT

Tailwind vs Vanilla CSS: Your project uses Tailwind CSS v4 extensively. I'll continue with Tailwind since the entire codebase depends on it. Switching to vanilla CSS would require rewriting every component.

IMPORTANT

OCR Endpoint: The real OCR requires an LLM with vision capabilities (GPT-4o / Claude). I'll implement it to work with OpenRouter's vision models when an API key is present, and return intelligent mock data when no key is set. This means it works in demos without needing a paid API key.

WARNING

No Database: The project currently has no database. I'll keep everything in-memory (Zustand on frontend, dict stores on backend) since this is a demo project. Firebase is mentioned in the structure but not implemented — I'll skip it to avoid scope creep.

health_score.py
Current: 4-factor weighted average (savings rate, bloat index, emergency fund, consistency).

Upgrade to 7-factor composite with temporal decay and trend analysis:

Factor	Weight	Method
Savings Rate	0.20	(income - spend) / income
Emergency Fund Coverage	0.15	min(savings / (6 * monthly_expenses), 1.0)
Subscription Bloat	0.10	1 - (unused_subs / total_subs)
Spending Consistency (CoV)	0.10	1 - min(σ/μ, 1.0) per category
Category Diversity (Shannon Entropy)	0.10	H(spending) / H_max — measures spending diversification
Anomaly Impact	0.15	1 - (anomaly_spend / total_spend) — penalizes outlier transactions
Trend Direction	0.20	Exponentially-weighted moving average slope of weekly spending — novel
Novel claim: "Temporal trend-weighted composite scoring that penalizes worsening trajectories more heavily than static overspending."

Return expanded response with per-factor breakdown for frontend visualization.

[MODIFY] 
anomaly_detector.py
Current: Global z-score across all transactions.

Upgrade to category-aware modified z-score with IQR fallback:

Compute z-scores per category (dining anomalies compared to dining mean, not global mean)
Use Modified Z-Score (median-based) for robustness against outliers
Add IQR method fallback for small sample sizes (< 10 in category)
Return severity levels: warning (2σ), alert (2.5σ), critical (3σ+)
Add explanation field: "This $1,450 Gucci purchase is 3.2σ above your average shopping spend of $87"
[MODIFY] 
persona_classifier.py
Current: Simple if/else heuristics.

Upgrade to hybrid rule-based + k-means clustering:

Build a 5-dimensional feature vector per user: [dining_ratio, shopping_ratio, savings_rate, subscription_count_normalized, spending_variance]
Pre-define 6 cluster centroids (no training data needed — use reference profiles)
Classify by minimum Euclidean distance to centroids
Keep rule-based overrides for edge cases (e.g., 0 spending = "The Ghost")
Add confidence score (inverse distance ratio)
Add traits array for radar chart data
[MODIFY] 
monte_carlo.py
Current: Fixed volatility, expense only in month 1.

Upgrade to proper stochastic modeling:

Accept planned_expenses as array (recurring vs one-time)
Model monthly income volatility (±5% normal distribution)
Model expense category inflation (2-8% annual depending on category)
Add P25 and P75 bands (5 total bands)
Support 12-month and 24-month projections
Return goal_hit_probability — probability of reaching a target balance
